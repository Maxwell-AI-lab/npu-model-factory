# 镜像验收场景矩阵

镜像的可信度 ≠ 跑通。**按变更类型选择验收深度**——不同场景验的东西不同，
本矩阵是 G1-G4 门禁（见 CONTRIBUTING.md）的"验什么"细化。
全景图：`assets/model-factory-workflow.html`（含本矩阵摘要卡）。

## 场景总览

| # | 场景 | 触发者 | 验收核心问题 | 验收深度 |
|---|---|---|---|---|
| S1 | 新模型适配完成 | ① 适配工程师 | 这个模型在 NPU 上训推都正确吗 | **全量 + 立基线** |
| S2 | 新特性集成 | ③ 特性开发 | 特性真的生效吗？代价是什么 | **实证 + 不回退** |
| S3 | 上游版本升级 | ④ 演进决策 | 升级没引入回归吗 | **全量回归** |
| S4 | 修复类更新 | ①/③ | 原问题修了吗？没修坏别的 | 定点 + 回归 |
| S5 | 例行重构/清理 | ①/③ | 行为完全等价吗 | **等价性证明** |

## S1 新模型适配完成（最重验收）

模型第一次在 NPU 上交付，**本版结果即后续所有版本的健康基线**。

| 维度 | 必验项 | 通过标准 | 工具 |
|---|---|---|---|
| 功能 | 推理生成正常 | 零乱码（多语言特征扫描 0 命中）、格式合规率 ≥ 98% | check_health / REWARD_DEBUG |
| 功能 | 训练一步不崩 | 无 EngineDead / aicpu 异常 / OOM | 日志崩溃特征 |
| 精度 | 训推一致 | **pearson ≥ 0.995 且无逐 step 漂移**（≥5 步） | check_health |
| 精度 | 训练有效 | score 在预期区间（如 GSM8K ~0.9）、响应长度正常非全截断 | check_health |
| 性能 | 立基线值 | 记录 step 稳态时间 / TPOT / 吞吐 → 写入健康基线表 | check_health + 报告 |
| 特性 | 模型专属算子路径 | 特有开关（SFA/indexer/投机等）按预期路径执行 | 探针（CKSUM/BFPROBE） |
| 交付 | manifest 登记 | tag / SHA256 / 组件版本 / 基线指标快照 | manifest.yaml |

> DSpark 归档即 S1+S2 复合实例：v30-fixed 验收建立了 pearson 0.9958~0.9970、
> TPOT 8.2~11.0、score ~0.91 的基线，65 步验证。

## S2 新特性集成（实证 + 不回退）

新特性（投机解码 / 新并行策略 / 新算子优化…）合入出镜像：

| 维度 | 必验项 | 通过标准 | 备注 |
|---|---|---|---|
| **特性生效** | 特性开关打开后走新路径 | 有实证指标（非"没报错"）：DSpark = 投机命中率/接受率 > 0、TPOT 实测加速比 | **核心**——特性静默失效是最常见事故 |
| **特性收益** | 与上一版 A/B 对比 | 量化收益写入验收报告（DSpark: TPOT 24.3→9.4 ms/tok = 2.6×） | 无收益的特性不上 |
| **精度不回退** | pearson/score 对照基线 | 与上一版镜像一致（±基线波动带内） | 用速度换精度不可接受 |
| **功能不回退** | 原有功能 | 生成质量/乱码/checkpoint 与基线一致 | |
| **可回退** | 特性开关关闭 | 关闭后走原路径正常（逃生门） | 出问题能一键关闭 |

## S3 上游版本升级（全量回归）

CANN / vllm-ascend / verl / torch_npu 版本组合变更（④ 五阶段决策晋级后）：

- **全量 G4 回归**：当作 S1 重跑（≥5 步全指标）
- **双镜像对比**：升级前后镜像逐项对账（组件 git 状态 / 关键文件 md5 / import 自检）——预期差异 = 升级的组件，出现预期外差异即停
- **性能对照**：step 时间 / TPOT 与升级前对比，回归超阈值（如 +10%）不晋级
- **历史坑复查**：knowledge/npu-gotchas 清单逐条不复现（升级常复活旧 bug）

## S4 修复类更新（定点 + 回归）

- **定点验证**：原 bug 场景复现通过（如 checkpoint 保存：跑到 save_freq 触发步确认存活）
- **回归**：check_health ≥5 步基线对照
- **影响面说明**：PR 说明修复触及的组件与文件，G1 门禁审查

## S5 例行重构/清理（等价性证明）

无行为变化的变更（脚本整理 / 文档 / 镜像瘦身）：

- **双镜像对比证明等价**：关键文件 md5 一致或差异均在说明范围内
- 冒烟（step 1 起跑正常）即可，无需全量回归

## 与门禁的对应关系

```
G1 代码门禁（PR）   ← 所有场景前置：patch 校验 + import 自检 + 自验输出
G2 构建门禁         ← S3/S5 的双镜像对比在此执行
G3 镜像门禁         ← 所有场景：冒烟 + manifest 登记
G4 运行门禁         ← S1/S2/S3/S4 的指标验收（深度按场景定）
```

## 记录要求

每次出镜像，验收结果记入 `docker/manifest.yaml` 对应 tag 条目
（场景类型 / 验收项结论 / 基线指标快照），形成可追溯的验收链。
