# 角色职责与输入输出

四角色完整定义。全景图（index.html）泳道与图下速查卡与此一致。

## ① 模型适配工程师

- **职责**：新模型在 NPU 上打通推理 / 训练 / RL 后训练
- **输入**：新模型发布（HF config + 权重 + 架构代码）；验证数据集
- **输出**：补丁（相对 stock 基线）+ 基础镜像（vN）；首次交付立健康基线
- **工作方式**：串行不跳层——9 宫格分析（无需 NPU）→ 推理验证 → 训练验证
  → RL 端到端（pearson ≥ 0.995）；每个结论有 file:line 证据链
- **交付动作**：补丁归档到 Git 分支（`git diff HEAD` 整树生成），
  验收完成交接 CIE 构建
- **不做什么**：不自行出镜像、不自行发布

## ③ 特性开发工程师

- **职责**：新特性集成与验证（投机解码 / 新并行策略 / 算子优化…）
- **输入**：①发布的基础版本（vN）+ Git 分支（patch 基线）
- **输出**：特性补丁 + 新版本镜像建议（vN.x-<特性名>）
- **工作方式**：外挂源码开发（fetch_sources 生成源码树 + 容器挂载即改
  即生效）→ 冒烟 → 整树重生成 patch → 提 PR 给 CIE
- **验收责任**：特性生效实证（加速比/接受率等量化指标，非"没报错"）+
  精度不回退（pearson/score 对照基线）+ 关闭可回退（逃生门）；
  PR 必附 check_health 输出（≥5 步）
- **不做什么**：不直接改容器内代码（改动只活在源码树+patch）、不自行合并

## CIE 工程师（版本集成 · 质量验证）

四步串行管线，不可跳步：

| 步骤 | 节点 | 动作 |
|---|---|---|
| 1. 代码合并管理 | Git 分支 | 收①补丁归档/③PR/②故障回流；G1 门禁；维护 patch 单一事实源 |
| 2. 质量门禁 | 门禁 | G2 双镜像对比 → G3 冒烟+登记 → G4 ≥5 步基线回归 |
| 3. 镜像制作 | 构建 | Dockerfile 可复现构建；tag 递增不覆盖 |
| 4. 正式版本发布 | 发布 | 定期班车 + Stable 晋级 + 三元组锁定 + 交付包（镜像+README+skill） |

- **输入**：①③的补丁（PR 形式，附自验输出）、②的故障回流
- **输出**：正式版本（面向②的完整交付包）
- **核心原则**：质量责任与开发责任分离。①③只管做对补丁；
  能不能合并、出不出镜像、何时发布由 CIE 独立判断
- **兼职责**：上游版本跟踪（CANN/vllm-ascend/verl 社区版本）与
  升级决策（五阶段评估，Canary→Stable）；CI 自动化维护

## ② 训练工程师

- **职责**：直接使用镜像跑训练（不开发特性）
- **输入**：发布版（镜像 + 使用 README + 使用侧 skill）+ 模型权重 + 数据集；
  三者版本由发布时三元组登记锁定，不匹配拒绝起跑
- **输出**：训练产物（checkpoint / 指标 / 业务结果）+ 故障回流
  （异常时 issue + 日志 + 复现步骤）
- **工作方式**：按 registry 登记取用 → docker load → preflight 体检 →
  训练 → check_health 对照基线
- **使用边界**：不自行改容器内代码；遇到问题走回流

## 两级发布（角色交接）

```
第一级 · 基础版（事件驱动）：① 验收完成 → CIE 即时发布 → 交接 ③
第二级 · 正式版（定期班车）：③ 多特性合入验收 → CIE 定期发布 → 交付 ②
```
